# تعليمات جاهزة لكوديكس (انسخ هذا الطلب إلى Codex عند وجود Hostinger)

المستودع: https://github.com/ali200903ali-stack/-

أنت مسؤول نشر واختبار نظام NineSoft. استخدم المستودع الموجود ولا تستبدله بتصميم تجريبي. راجع أولاً README.md وdocs/DEPLOY_HOSTINGER_AR.md وdocs/STATUS_AR.md واختبارات tests/accounting_smoke.php.

المطلوب في عملية النشر:
1. راجع GitHub Actions وتحقق أن workflow PHP accounting checks ينجح وأن Windows EXE وAndroid APK يبنيان، وأصلح أي أخطاء موثقة قبل التوزيع.
2. افحص جميع ملفات PHP وJavaScript واعتمد اختبار end-to-end على خادم تجريبي. تأكد من أن الواجهة تطابق NineSoft المرجعي قدر الإمكان وأن الأقسام الـ19 تعمل وفق نطاقها المعلن.
3. اطلب الوصول إلى استضافة Hostinger من القنوات الآمنة (لا تطلب نشر كلمات المرور في GitHub أو ملفات دردشة علنية). أنشئ قاعدة MySQL/مستخدماً/نطاق HTTPS حسب docs/DEPLOY_HOSTINGER_AR.md.
4. ابنِ أو نزّل أحدث حزمة من GitHub Actions باسم Hostinger Web ZIP، ثم انشر ملفات PHP والواجهة على document root. أنشئ config.local.php على الخادم فقط، بقيم MySQL الفعلية وتوكن تثبيت عشوائي قوي. شغّل install.php مرة واحدة، ثم احذفه.
5. اختبر المصادقة والصلاحيات والفروع والمبيعات والمشتريات والمرتجعات وسندات القبض والصرف والقيود وميزان المراجعة ومزامنة عملاء ويب/ويندوز/أندرويد.
6. اعمل نسخ قاعدة MySQL يومية مع تجربة استعادة في staging. قيّد الوصول إلى الملفات الحساسة وفرض HTTPS وتحقق من أن أسرار العميل لا تُضمّن في JS أو APK/EXE.
7. لا تصف WASL أو WhatsApp أو المزامنة Offline بأنها جاهزة؛ هذه تحتاج مفاتيح وموافقات API مستقلة.
8. أصدر تقريراً بنتائج الاختبارات، أخطاء معلقة، عنوان الويب النهائي، روابط Artifacts الخاصة بـEXE وAPK، وخطوات التسليم. لا تعلن الاستخدام الإنتاجي بالأموال الحقيقية قبل مراجعة أمنية ومحاسبية وتوثيق النجاح.

الأولوية: سلامة القيود المالية > أمن الصلاحيات > الاعتمادية > تطابق التصميم.
