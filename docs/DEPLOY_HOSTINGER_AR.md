# نشر NineSoft على Hostinger (خطوات لكوديكس أو لمسؤول السيرفر)

## افتراضات الاستضافة
- استضافة Hostinger تدعم PHP 8.2 أو 8.3، PDO MySQL، قاعدة MySQL/MariaDB، SSL من لوحة hPanel، ملفات .htaccess وإعادة التوجيه.
- لن تحتاج إلى npm ولا Composer للويب. مجلدات Android وWindows للـbuild فقط؛ لا تُشغّلها داخل public_html.
- مطلوب اسم نطاق/نطاق فرعي مخصص مثل https://accounts.example.com؛ تأكد من أن SSL صالح ويعمل.

## 1) إعداد قاعدة البيانات
افتح Hostinger hPanel -> Websites -> Manage -> Databases -> MySQL Databases (قد تختلف أسماء القوائم حسب الإصدار). أنشئ قاعدة بيانات مستخدمها بامتيازات على القاعدة نفسها فقط. سجّل host/port/database/user/password في مدير أسرار خارجي، لا في GitHub.

## 2) رفع ملفات الويب
- الأسهل: من GitHub -> Actions -> Hostinger Web ZIP، نزّل Artifact باسم NineSoft-Hostinger-web، ثم فك ملف NineSoft-Hostinger.zip وارفع محتوياته إلى document root. بديل ذلك استنسخ محتوى المستودع من https://github.com/ali200903ali-stack/-.
- ضع جذر تطبيق PHP في document root للنطاق أو subdomain (غالباً public_html)، بحيث توجد index.php وapi.php وschema.sql وbootstrap.php وassets/ في المكان نفسه.
- أبق .htaccess من المستودع، وتأكد أنه يُقرأ؛ اختبر أن GET /schema.sql و GET /config.example.php و GET /src/Accounting.php تُرجع 403، وإلا حرّك الإعدادات والملفات الحساسة خارج webroot وعدّل المسارات أولاً.
- مجلد storage/ يجب أن يكون قابلاً للكتابة من PHP، مع منع الوصول المباشر من الويب. عدم إمكانية كتابة ملف القفل لا يمنع التثبيت لكن ليس مرغوباً.

## 3) إعداد الأسرار (مرة واحدة)
انسخ config.example.php إلى config.local.php داخل الخادم فقط. عدّل الحقول:
  db_host, db_port, db_name, db_user, db_pass, app_url, timezone, install_token.
- app_url يشير إلى عنوانك HTTPS.
- install_token قيمة عشوائية قوية لا تقل عن 32 حرفاً، وليس المثال الموجود في المستودع.
- لا ترفع config.local.php إلى GitHub مطلقاً؛ هو ضمن .gitignore.

## 4) تثبيت قاعدة البيانات
1. افتح https://YOUR-DOMAIN/install.php.
2. أدخل install_token، اسم مدير النظام، بريد إلكتروني صالح، وكلمة مرور لا تقل عن 12 حرفاً.
3. سيُنشئ الجداول وشجرة الحسابات والفرع الرئيسي وحساب العميل النقدي والمدير، مع منع تكرار التثبيت إذا وجد مستخدمون.
4. بعد نجاح الدخول، احذف install.php من الخادم أو امنعه في إعدادات Apache/LiteSpeed؛ لا تعرض معالج التثبيت بشكل دائم.

## 5) فحص الخادم
- افتح /index.php عبر HTTPS واستخدم تسجيل الدخول.
- أنشئ صنفاً وجرب رصيداً افتتاحياً ثم عملية بيع مسودة وترحيلها، وتحقق من تغير الرصيد وظهور القيود.
- جرب شراء وتحديث التكلفة المتوسطة، وسند قبض، وميزان مراجعة متوازن.
- تحقق من جلسات وصلاحيات كاشير ومحاسب ومدير.
- افحص سجلات PHP على Hostinger لأي أخطاء.
- افرض HTTPS على النطاق. لا تستعمل كلمات مرور مشتركة أو حساب مدير عام.
- اضبط نسخ احتياطية تلقائية منتظمة لقواعد MySQL وملفات config.local.php، واختبر الاستعادة في بيئة منفصلة.
- أزل/قيد إمكانية التشغيل العام لمسارات الاختبارات والأدوات (.htaccess يرفضها افتراضياً).

## 6) ربط Windows وAndroid
- ملفات المشروع داخل clients/windows وclients/android هي مصدر للبناء.
- من GitHub -> Actions -> Windows EXE نزّل ملف EXE من Artifacts بعد النجاح.
- من GitHub -> Actions -> Android APK نزّل Debug APK من Artifacts بعد النجاح (للنشر الرسمي يلزم توقيع Release خاص).
- عند أول تشغيل اختر عنوان موقع NineSoft الدقيق عبر HTTPS. بذلك يستخدم الويب وويندوز وأندرويد خادماً وقاعدة بيانات واحدة.
- احذر من مشاركة مستند محاسبي بعد فصل الإنترنت: لا يوجد Offline Sync؛ واجهة PWA تقرر ألا تخزّن بيانات مالية كذاكرة مؤقتة.

## 7) متطلبات ما قبل التشغيل الفعلي بالأموال الحقيقية
- استخدم بيئة تجريبية staging للاختبارات، ومراجعة المحاسب القانوني لشجرة الحسابات والضرائب وسياسة التكلفة والمرتجعات والفترات المالية.
- اختبارات أمان (CSRF/XSS/SQL Injection/IDOR/Brute force/Session fixation) ومراقبة دخول وقيود أمنية متقدمة.
- نظام استعادة واسترداد من النسخ الاحتياطية، تأمين الوصول، مراقبة أعطال، تدقيق الأرقام والأرصدة وحساب الضريبة وفق القوانين المحلية.
- تهيئة مفاتيح وموافقة مزود WASL/WhatsApp إن احتجت تكاملات؛ حالياً غير متصلة.

## ملاحظة
ملف JSON الصادر من قسم النسخ الاحتياطي ليس نسخة SQL كاملة ولا يملك زر استعادة. اعتمد mysqldump/backup hPanel لنسخ واستعادة سليمة.
